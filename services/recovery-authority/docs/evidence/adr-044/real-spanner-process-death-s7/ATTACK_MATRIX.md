|---|---|---|---|

| E | Matching operation ID treated as sufficient acceptance provenance | **Fails closed** — same reasoning as D; the decision computation never inspects `operation_id` at all | `DECISIVE_TRIAL.md` |

| K | Multiple restarts eventually bypass the unresolved state | **Fails closed** — 3 independent restarts (0s/2s/5s apart) all converged identically; no attempt count parameter exists anywhere in the decision logic that could allow a later attempt to differ from an earlier one | `DECISIVE_TRIAL.md` |
| L | `NEW_EPOCH_REQUIRED` not asserted | **Does not occur** — explicitly asserted true in every trial (decisive + all 3 restarts) | `DECISIVE_TRIAL.md` |
| M | A cleanup/recovery helper silently rewrites state | **No such helper exists** — `epoch.Terminate` performs no I/O of any kind (by its own doc comment and implementation); no other function in `rotationcommit`/`epoch`/`bootstrap` mutates Spanner or GCS state outside the two already-reviewed write paths (`completeRawCommit`'s own Commit, `CreateExactIfAbsent`) | `epoch/state.go` |
| N | The test harness itself persists hidden acceptance material | **Does not occur** — the qualification harness (`realcloud_spanner_processdeath_test.go`) writes nothing to Spanner or GCS outside the same real production mutations/witness-write paths already reviewed elsewhere in this codebase; it introduces no new persistence mechanism, cache, or side-channel |
