# Explicit Limitations

1. **This does not prove ADR-045 production administrative independence.** The qualification environment is disposable and same-organization (same GCP organization as `emg-platform-staging`), matching Track D/E's own already-disclosed limitation. `PRODUCTION_ADMINISTRATIVE_INDEPENDENCE_RESULT = NOT ESTABLISHED`.
2. **This does not authorize production deployment, production approval, Track F→S7 promotion, or end-to-end genesis against real production infrastructure.**
3. **Two previously disclosed qualification gaps remain honest, open gaps, exactly as instructed — neither was forced or fabricated this wave:**
   - **A. Process-death during a real, ambiguous Spanner commit** — not exercised. Reproducing a genuine mid-RPC process death during an ambiguous Commit against real Cloud Spanner safely and deterministically was judged out of safe scope for this qualification; the classification logic for this case is already unit/emulator-tested (Wave 1 Track A), but a real-cloud reproduction of the ambiguous-outcome-during-process-death scenario specifically was not attempted.
   - **B. Ambiguous real GCS witness write** — not exercised. A genuinely ambiguous (neither confirmed-success nor confirmed-failure) real GCS write requires inducing a specific network/timeout condition against the real GCS API that could not be safely and deterministically reproduced without risking corrupting the qualification's own witness bucket state.
4. **A new, real, empirically-discovered timing fact** (not a gap, but worth stating plainly): Cloud KMS crypto-key-version DISABLE state was observed to take longer than one minute but less than five minutes to propagate to whatever backend actually served the qualification's `AsymmetricSign` calls in this trial. This is not a security defect — the architecture's own fail-closed design correctly classified the affected attempt as `OutcomeUnresolved` once the disable had propagated — but it means "disable a key and immediately assume no further signing is possible" is not a safe operational assumption without allowing for this window, exactly analogous to Track D's already-documented IAM-propagation finding.
5. The witness bucket and 3 objects remain under real Bucket Lock retention past this session's end (see `CLEANUP.md`) — final bucket deletion is a deferred follow-up action, not something this task bypassed.
6. The Track F genesis orchestrator (`trackfgenesis`, `trackfpincapture`, `trackfledgerwrite`, `trackfgenids`, `trackfverifyevidence`) were diagnostic-only Go programs built from the real, unmodified repository packages via a local `replace` directive into a disposable build context. None were committed to the repository; all existed only in scratchpad/disposable container images, deleted along with the rest of Track F's disposable resources.
7. Not every theoretically possible attack-matrix permutation was independently re-exercised with a live test this wave where the underlying boundary was already exhaustively, empirically proven in an earlier track (Track C's KMS/pin-store/ledger boundaries; Track D's WIF namespace-isolation and revocation-timing findings; Track E's TLS/NetworkPolicy findings) — re-proving identical ground was judged redundant rather than load-bearing for Track F's own integration scope. Each such omission is stated explicitly in `ATTACK_MATRIX.md` rather than silently assumed.
