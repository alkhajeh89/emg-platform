# Explicit Limitations

1. **Track E proves real Kubernetes/TLS/network behavior in the disposable `ra-k8s-qual` qualification namespace only.** It does not prove, and is not claimed to prove, anything about the real `emg-staging` namespace's own (currently zero) NetworkPolicy posture beyond the specific defect and fix described in `DNS_NETWORKPOLICY_DEFECT.md`.
2. **This does not prove ADR-045 production administrative independence.** The qualification environment is a disposable, same-organization environment (same GCP organization as `emg-platform-staging`); it does not exercise a genuinely separate Cloud Identity/Workspace trust domain. `PRODUCTION_ADMINISTRATIVE_INDEPENDENCE_RESULT = NOT ESTABLISHED`, unchanged from Track D.
3. **This does not authorize production deployment or production approval.** Track F end-to-end genesis and S7 were not started, per explicit instruction.
4. **The external-egress limitation is real and unresolved**: plain Kubernetes `NetworkPolicy` cannot express FQDN-scoped allow rules for Google APIs (Spanner/GCS/KMS); the qualification's egress rules for this traffic are scoped only to port 443, not to specific Google API endpoints. This is a genuine production-readiness gap if tighter API-level egress control is ever required, and is reported plainly rather than solved with a brittle static IP range.
5. Several attack-matrix items were not independently re-exercised this wave because they are structurally guaranteed by Kubernetes itself (`spec.serviceAccountName` immutability) or were already exhaustively, empirically qualified with real resources in prior waves (Track C's KMS/pin-store/ledger boundaries; Track D's WIF namespace-isolation and revocation-timing findings) — re-proving them here was judged redundant rather than load-bearing for Track E's own Kubernetes/TLS/network scope.
6. The qualification's `recovery-authority` deployment does not exercise real Spanner or GCS connectivity (Option B, `README.md`) — `compose()`'s readiness gate does not require it, and this ground was already covered with real resources in Wave 1/Track C. `POST /v1/verify`, the only endpoint that would exercise it, was never called in this qualification.
7. A diagnostic-only Go client (`trackediag`) was built from the real, unmodified `signerrpc`/`protocol` packages via a local `replace` directive to exercise the real TLS+bearer-auth path end-to-end; this client was never committed to the repository and existed only in scratchpad/disposable build contexts, deleted along with the rest of the qualification's disposable resources.
