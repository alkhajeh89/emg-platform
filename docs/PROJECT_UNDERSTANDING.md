\fs36 \cf0 Architecture Summary\
\pard\tx220\tx720\pardeftab720\li720\fi-720\sa240\partightenfactor0
\ls1\ilvl0
\fs24 \cf0 \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Authoritative Storage
\f1\b0 : PostgreSQL acts as the single authoritative source of truth for the system, specifically owning the append-only, hash-linked revision log, the per-tenant head pointer, and the outbox.\
\ls1\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Serving Projection
\f1\b0 : Neo4j functions purely as a queryable topology projection (the serving graph) that is derived from and fully rebuildable from the PostgreSQL revision log.\
\ls1\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Write Path Independence
\f1\b0 : Neo4j is completely off the write open and commit path; write transactions load snapshots from and write directly to PostgreSQL. Writes remain available even if Neo4j is down.\
\ls1\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Read Path & Fallback
\f1\b0 : Reads prefer the Neo4j serving projection but automatically fall back to the PostgreSQL JSON snapshot (graph_json) if Neo4j is unavailable.\
\ls1\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Multi-Tenancy Layout
\f1\b0 : The system utilizes a shared-schema multi-tenancy model where every persisted row in PostgreSQL and every node/edge in Neo4j carries a mandatory tenant_id.\
\pard\pardeftab720\sa298\partightenfactor0

\f0\b\fs36 \cf0 Design Principles\
\pard\tx220\tx720\pardeftab720\li720\fi-720\sa240\partightenfactor0
\ls2\ilvl0
\fs24 \cf0 \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Storage Technology Independence
\f1\b0 : Knowledge consumers are decoupled from the underlying database tech via a strict extension point (SemanticQueryExecutor) and abstract data protocols.\
\ls2\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Never-Overwrite Durability
\f1\b0 : All graph alterations are stored as append-only forward revisions; graph state rollbacks are achieved by creating a new forward revision instead of performing destructive updates.\
\ls2\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Fail-Closed Security
\f1\b0 : Authorization and policy engines operate on a default-deny, fail-closed mechanism for both human and service principals.\
\ls2\ilvl0
\f0\b \kerning1\expnd0\expndtw0 \outl0\strokewidth0 {\listtext	\uc0\u8226 	}\expnd0\expndtw0\kerning0
\outl0\strokewidth0 \strokec2 Data Conformance via Construction
\f1\b0 : Core domain entities carry strict fields like classification, trust scores, and provenance references inherently by construction, preventing unvalidated mass-assignment.\
